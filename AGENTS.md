# Инструкции для агентов

При создании коммитов, которые будут отправлены в удалённый репозиторий (`git push`), обязательно указывайте соавторство Codex, добавляя в конец сообщения каждого коммита следующий Git-трейлер:

```text
Co-authored-by: Codex <codex@openai.com>
```

По умолчанию запускайте команды Git без параметра `-c safe.directory`. Используйте `git -c safe.directory="<абсолютный путь к текущему репозиторию>" ...` только после того, как обычная команда Git завершилась ошибкой `fatal: detected dubious ownership in repository`, и применяйте этот параметр разово — только к конкретной команде и только для текущего репозитория. Не изменяйте ради этого глобальную или системную конфигурацию Git, не добавляйте `safe.directory=*` и не отключайте проверку владения для всех репозиториев.

## Сборка PDF из LaTeX

- Собирайте резюме установленным MiKTeX (`pdflatex`). Для каждого файла `.tex/<направление>/<имя>.tex` создавайте итоговый файл `.pdf/<направление>/<имя>.pdf`; существующие направления — `General`, `Java` и `.NET`.
- Перед каждой сборкой создавайте временную папку `.tex/<направление>/build` и направляйте в неё все результаты `pdflatex`, включая промежуточный PDF и файлы `.aux`, `.log`, `.out`, `.synctex.gz` и другие. Не оставляйте временные файлы рядом с `.tex` и не помещайте их в `.pdf`.
- При необходимости запускайте `pdflatex` дважды для корректного формирования ссылок. После успешной сборки переносите итоговый PDF из `build` в соответствующую папку `.pdf/<направление>/` с сохранением имени и проверяйте наличие файла назначения.
- Только после успешной генерации и проверки PDF удаляйте созданную для этой сборки папку `build`. Перед удалением проверьте точный абсолютный путь и убедитесь, что он оканчивается на `.tex/<направление>/build`; не удаляйте более широкую директорию.
- Если сборка завершилась ошибкой, сообщите об ошибке и сохраните `build` со всеми диагностическими файлами до завершения диагностики.
